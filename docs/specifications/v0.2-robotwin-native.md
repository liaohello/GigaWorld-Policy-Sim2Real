# V0.2 — Native RoboTwin closed loop over the 14-D Aloha-AgileX contract

Status: **PASS (interface) / FAIL (task)** — measured 2026-10-23. The policy
interface works; the zero-shot policy does not solve the task. Both statements
are load-bearing and must be reported separately (see `AGENTS.md`).

## Goal

Drive RoboTwin 2.0 `beat_block_hammer / demo_clean` with GigaWorld-Policy 0.5 in
closed loop through the simulator's native 14-dimensional action interface,
without altering the simulator's control semantics or the policy's output
semantics.

## Acceptance criteria

### Data and environment

- [x] The renderer returns live RGB, not a blank or cached buffer.
      *Three cameras, 240×320 uint8, min 0 / max 255, non-blank and non-constant (A1).
      The smoke probe does not command joints, so its three frames are identical (A2);
      temporal variation is established by the collected episode instead (A3).*
- [x] One expert episode is collected into a fresh output directory; the original
      dataset is untouched (modification times unchanged).
- [x] The demonstration contract is documented and machine-checked: 14 dims, all
      finite, 15 Hz, `action[t] == state[t+1]` (B1).
- [x] A LeRobot v3 conversion is verified against the source frames before it is
      scaled to the full set (B2), then all 50 episodes convert (B3).
- [x] Expert replay reproduces the recording under the same controller
      (`check_success() = true`) — this validates the *data*, not the policy (B4).

### Policy interface

- [x] Observation mapping is explicit and asserted: three named cameras in RGB,
      14-D packed state in the order `[left_arm, left_ee, right_arm, right_ee]`,
      instruction string, and a fixed text embedding.
- [x] The adapter does **not** re-apply denormalization or delta→absolute
      conversion: the policy pipeline already emits physical joint targets.
      Double conversion is treated as a defect, not a tweak.
- [x] Action chunks are validated before use: shape `[48, 14]`, finite, and the
      executed prefix is configurable (`execute_action_chunk`).
- [x] Normalization convention is stated explicitly and is consistent with the
      C++ path where the two are compared (see `docs/experiments/robotwin-gwp-native-results.md`, defect E-1).

### Closed-loop execution

- [x] Fixed seeds run end to end without NaN, shape errors, or protocol errors (E1, E2).
- [x] Every episode leaves a video, a result record, and (optionally) a per-call
      action trace (E3).
- [x] Consecutive episodes reset cleanly; a stale server-side cache must not
      condition episode *n+1* on episode *n*.
- [x] Expert replay and policy control appear in separate rows of every report.
      A policy run is never described as successful on the strength of a replay.
- [ ] Task success above zero.

Result: **0/3 seeds** reached success within the 400-step budget. The arm's joint-1
command drifts monotonically from ~0.85 rad to ~44 rad while the measured joint
saturates at the SAPIEN limit. Four episodes, two normalization conventions, same
shape of failure — so this is a policy/embodiment fit problem, not a plumbing
problem.

## Explicit non-goals

- No fine-tuning, no seed search, no prompt engineering to manufacture a success.
- No substitute action stream (expert, scripted, or replay) is ever reported as
  policy control.
- No claim about SO101 or real hardware.

## Reproduce

`configs/experiments/robotwin-native-closed-loop.yaml` plus
`scripts/evaluate/closed_loop.sh`; the server side is `scripts/infer/gwp_server.sh`.
